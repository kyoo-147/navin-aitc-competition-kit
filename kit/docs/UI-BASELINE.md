# Optional UI Baseline

Use this guide only when the live challenge needs a product surface.

- Give each screen one clear primary task.
- Follow supplied references and design tokens instead of inventing a new system.
- Keep typography, spacing, radius, color, icons, and actions consistent.
- Use color for state, priority, brand, data, or action, not decoration.
- Prefer progressive disclosure over dense dashboards.
- Test long names, nulls, missing media, overflow, large values, long lists, loading, empty, success, and error states.
- Put friction around irreversible actions.
- Use motion only to explain state or spatial change.
- Prefer clearer and simpler over more impressive.

Do not spend competition time polishing UI before the core user flow, integration, and evidence work.
